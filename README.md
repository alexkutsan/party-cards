# Party Cards

Карточки для игр компанией. Телефон **ведущего** показывает только QR-код. Игрок сканирует его своим телефоном и читает карточку у себя — текст не появляется на общем экране.

Сайт: <https://alexkutsan.github.io/party-cards/>

Исходные тексты лежат в `source/` (три markdown-файла). `prototype/` — ранний офлайн-прототип в одном HTML-файле. Сайт, который публикуется, собирается в `dist/` скриптом `build.py` и не коммитится.

## Как устроена игра

1. На главной ведущий выбирает раздел и игру. Раздел «Финал 18+» открывается после подтверждения, что всем есть 18 и игра добровольная. Экран «Перед игрой» — согласие, калибровка, сигналы.
2. Правила, потом колода. Можно включить несколько колод и отфильтровать уровни (🟢🟡🔴🔥💞). У «Однорукого бандита» два режима: комбинация «что / где / как» и «Колесо желаний». Число игроков от 2 добавляет в комбинацию «кто → кому».
3. Кнопка **«Взять карточку»** снимает карточку с колоды без повторов, пока колода не кончится. На экране ведущего — крупный QR-код, название игры и сколько карточек осталось. Текста карточки там нет.
4. Игрок открывает ссылку из кода и видит только эту карточку на весь экран. **«Закрыть / следующий»** убирает код. Если закрыть его случайно кнопкой «назад», код можно показать ещё раз — карточка уже не вернётся в колоду, пока колоду не сбросят.
5. QR собирается в браузере, без внешнего API. После первого открытия на GitHub Pages service worker сохраняет приложение, и уже открытая версия работает офлайн.

Повторно выпавшие карточки и выбранные колоды помнит `localStorage` этого телефона.

## Ссылки

Каждая карточка — свой адрес. В ссылке нет текста карточки, только короткий непрозрачный идентификатор (хеш от раздела, названия игры, колоды и номера). По номеру в адресе следующую карточку не угадать.

- Одна карточка: `https://alexkutsan.github.io/party-cards/c/<id>`
- «Однорукий бандит» целиком: `https://alexkutsan.github.io/party-cards/m/<что>~<где>~<как>`
- То же с парой игроков: `https://alexkutsan.github.io/party-cards/m/<что>~<где>~<как>~<кто>-<кому>`

Пример формы, не живая карточка: `https://alexkutsan.github.io/party-cards/c/aBcDeFgHiJk`

Идентификатор стабилен, пока не меняются название игры, имя колоды и номер строки. Правка самого текста ссылку не ломает. Сами колоды в открытом статическом сайте технически можно прочитать в исходниках страницы — адрес и QR этого не показывают.

## Как править карточки

Тексты только в `source/`:

- `1_uznat_glubzhe.md` — «Узнать глубже»
- `2_posmeyatsya.md` — «Посмеяться»
- `3_final_18.md` — «Финал 18+» (для взрослых по взаимному согласию), 608 карточек. Вместе с двумя другими файлами карточек на сайте 1603. В «Бутылочке 18+» карта «Финальная» по-прежнему выпадает последней, даже если в колоде после неё добавлены новые номера.
- `4_summa_stavki_18.md` — «Сумма и ставки», тоже в разделе «Финал 18+». Готовый набор: `https://alexkutsan.github.io/party-cards/s/<id>`. Случайный: `https://alexkutsan.github.io/party-cards/s/r.<вопрос1>.<вопрос2>.<вопрос3>.<вопрос4>.<вопрос5>.<вопрос6>`. На телефоне игрока счётчик, ответы не уходят с устройства.

Игра — это заголовок `## Игра N. «Название»`, затем правила, затем одна или несколько колод:

```markdown
### Колода: Название колоды

1. Текст карточки дословно
2. 🟢 Карточка с уровнем
```

Уровень — это эмодзи в начале строки (или в названии колоды, если на строке его нет): 🟢 🟡 🔴 🔥 💞. Номер в колоде — тот, что стоит в markdown. Текст карточки попадает в приложение как есть.

Дальше:

```bash
python3 build.py
```

Скрипт печатает число карточек по каждой колоде и сверяет его с исходником. Если строка внутри колоды не разобралась, сборка падает.

Закоммитьте markdown и запушьте в `main`. Workflow `.github/workflows/pages.yml` заново соберёт сайт и выложит его на Pages. Локальную папку `dist/` коммитить не нужно.

Посмотреть у себя:

```bash
python3 build.py
python3 serve.py
```

Откроется <http://127.0.0.1:8080/party-cards/> — с тем же префиксом, что и на GitHub Pages, и с запасной `404.html` для прямых ссылок на карточки. На локальном адресе service worker по умолчанию выключен, чтобы правки были видны сразу. На `github.io` он включается.

Проверка, что открываются все разделы и игры (правила, QR и прямые ссылки на карточки):

```bash
npm install
npx playwright install chromium
python3 build.py
python3 serve.py
```

В другом окне: `node tests/smoke.mjs http://127.0.0.1:8080/party-cards/`. Тот же скрипт запускается в GitHub Actions до публикации. Для уже выложенного сайта: `node tests/smoke.mjs https://alexkutsan.github.io/party-cards/`.

Другой префикс (например, сайт пользователя в корне домена): `BASE_PATH=/ python3 build.py`.

## GitHub Pages — один ручной шаг

Автоматический деплой заработает только после того, как в репозитории включён источник **GitHub Actions**. Это нельзя сделать из самого workflow, пока Pages ещё не переключены.

1. Откройте репозиторий на GitHub → **Settings** → **Pages**.
2. В блоке **Build and deployment** поставьте **Source: GitHub Actions** (не «Deploy from a branch»).
3. Сохраните. Если GitHub предлагает включить Pages — включите.
4. Влейте изменения в `main`. На вкладке Actions должен пройти workflow **Deploy GitHub Pages**.
5. Сайт появится по адресу <https://alexkutsan.github.io/party-cards/>.

Пока источник не переключён, деплой обычно падает с ошибкой вроде `Get Pages site failed` / `Not Found` — это как раз тот ручной шаг.

Репозиторий должен быть доступен гостям без входа в GitHub. На бесплатном плане Pages для приватных репозиториев нет, так что для компании репозиторий нужен **публичный** (либо платный план, где Pages разрешены и для приватных). Телефоны игроков открывают только страницу карточки, но сам сайт при этом публичный.

Если репозиторий переименуют, поправьте `BASE_PATH` в `.github/workflows/pages.yml`: префикс должен совпадать с именем репозитория (`/<repo>/`).
